## Accomplished

**Marquetry** (Marginalia 262, `music/marquetry`) — a deliberately small
homegrown ModularGrid for planning eurorack rack rearrangements. Manual
placement with live HP accounting; no solver, no power model, no depth
constraints. Registered with Bosun, live on `:3001`.

### The data question came first

Started by asking whether the modular inventory was in the Infovore larder.
Mostly not. `infovore-larder-db/gear-manager/gear.db` (identical on MBP and
MacMini) holds 208 Reverb purchases with hand-curated keep/for_sale/gone — good
ownership signal, but no HP, no depth, no power, no rack assignment. The
dimensions turned out to live in `~/Documents/Modular grid list.numbers`, a
Jan-2025 ModularGrid rack export: 97 modules with HP width and depth in mm.
Extracted with `numbers-parser`.

Neither source is sufficient and they disagree — the ModularGrid export predates
Mimeophon, athru, Shelves, Tides, Clouds, Braids, Streams and Cursus Iteritas
Alia. So `tools/build_catalogue.py` joins them: dimensions from ModularGrid,
ownership from gear.db. The join is fuzzy, so rather than guess silently every
doubt goes to `data/reconciliation-review.csv` with a typed issue, and
`data/overrides.json` / `data/aliases.json` record decisions and survive
regeneration.

**121 entries, 93 placeable, 966 HP, 43 flagged** (from 123/91/932/48 after
Andrew adjudicated the four blocking rows).

### The app

PureScript/Halogen over static JSON: racks drawn to true HP width, an unplaced
pool, `localStorage` persistence with JSON export. `Marquetry.Arrange` is
Halogen-free and holds the one invariant — a module is in at most one row,
enforced by `insertAt` removing before it adds. 13 tests.

Three rounds of interaction work, each from Andrew testing it:

1. **Uneven panel heights.** Rail and pool were both letting content set the
   height; a flex line stretches to its tallest item, and the tallest was
   whichever narrow module had the longest vertical label. Everything is 3U, so
   height is a constant — both now take `--rail-h`. Pinning it exposed that
   narrow labels were centred and clipped at *both* ends; anchored at the top
   they degrade to "FHX-8GT Gate Expa…".
2. **Carets invisible on an empty row.** One 2px caret at 25% opacity on a 630px
   rail read as "you can only drop at the left edge". The trailing caret now
   flex-grows to fill the free HP and tints while armed.
3. **Drag and drop.** Added on top of click-to-place; both share state and
   interleave.

## Decisions Made

- **Manual arrange + validate, not an auto-packing solver.** The useful thing is
  seeing what fits, not being told an arrangement.
- **Rows hold an ordered list, not x-offsets.** Eurorack has no gaps that
  matter, so a position is an index. Move-within-row, move-between-rows and
  move-between-cases become literally the same operation.
- **Uncertainty is a first-class output.** The review CSV is as much the
  deliverable as the catalogue. Twelve HP values Claude supplied from published
  specs are deliberately left un-`reviewed` so they keep resurfacing.
- **Panels are drop targets split at their midpoint**, not just the carets. A
  caret is 10px wide — a fine click target and a miserable drag one.
- **The bundle step lives in the Bosun `startCommand`**, matching Producing With
  Your Feet: `static/index.js` is gitignored, so serving a prebuilt artifact
  would break on a fresh clone.

## Gotchas worth remembering

- **`event.currentTarget` is null by the time Halogen's `handleAction` runs** —
  dispatch has finished. Use `event.target`, with `pointer-events: none` on
  child spans so it resolves to the element you meant.
- **CSS `:hover` does not fire during an HTML5 drag.** Hover feedback has to be
  tracked in state from dragenter/dragleave.
- **A token-overlap score divided by the *shorter* name** rates "ochd" against
  "ochd expander" a perfect 1.0. Jaccard instead, and keep substring-containment
  strictly below 1.0 so an exact match always outranks it.
- **Two tabs on the same origin share `localStorage`.** Driving the app in an
  automation tab wrote into Andrew's live testing session. Use a different port
  to isolate.
- **`:3100/api/ports/suggest` and `:3022/api/ports/suggest` disagree.** Bosun's
  is the one the router reads.

## Explored But Not Pursued

- Depth constraints and power budgeting — both dropped from scope. Depth exists
  for 91 of 97 modules; power exists nowhere.
- Hylograph layout libs — checked the API index, but rows of rectangles packed
  left-to-right need no layout machinery.

# Session 2 — hylograph-graph-json: a JSON ingestion contract

Prompted by a cross-Claude proposal (Paul's side, producer **blobgraphs** — a
DuckDB/SQLite extension) that Hylograph publish one canonical node/link JSON
decoder so external tools have a stable shape to target.

## Accomplished

- **New package `purescript-hylograph-graph-json`**, building green: 12 test
  groups, no warnings in our own source. Not published — deliberately.
  - `Hylograph.Graph.JSON` — the wire format, one bidirectional `JsonCodec`,
    plus a tolerant `decodeGraph` and a `String`-error `parseGraph` so the
    entry path needs no codec vocabulary.
  - `.Adapters` — `toGraph` / `toWeightedDigraph` / `toDAG` + validation.
  - `.Sim` — `toSim` / `resolveLinks`; the id→index resolution every showcase
    has been reimplementing, reporting unresolved links rather than dropping
    them.
  - `.Diagnostics` — pure structured `report` / `hasProblems`.
- **`graph-json-check` CLI** (`cli/` workspace package, kept separate so the
  library stays node-free). Exit 0 clean / 1 on decode failure or
  dangling-and-duplicate. Renders the diagnostics report.
- **Worked example** (`examples/force-graph/`) — JSON file to rendered force
  graph, verified in a browser, not merely compiled.
- **Two KB documents**: `plans/hylograph-graph-json.md` (design, the producer's
  answers and their triage) and `research/hylograph-public-api-leaks.md` (two
  ecosystem findings plus a postscript on what tooling would have caught them).

## Decisions Made

- **Codec values, not `DecodeJson` instances** — Elements entry 127. For a
  package whose whole job is publishing a wire contract, the decisive reason is
  that a codec is bidirectional by construction, so `encodeGraph` is a real
  reference implementation an external producer can validate against.
- **Boundary contract, not internal.** The proposal suggested making the JSON
  shape the internal contract; declined. The graph types are plural and
  polymorphic on purpose.
- **A producer's preference is evidence, not a specification.** Each of
  blobgraphs' asks was triaged against a generic consumer. `weight :: Number`
  was adopted on independent grounds, not on their CSR reasoning. Anything
  DuckDB-shaped was ruled out of scope and recorded so it stays out.
- **Absorb unrecognised keys into `attributes`** rather than dropping them.
  `{"id":"a","group":1}` is the commonest node shape in the wild and we were
  silently discarding `group`. The cost is that typos become invisible, which
  is why the checker exists and reports absorbed keys.
- **Publishing waits.** Registry versions are immutable; `nodesCodec` /
  `linksCodec`, `weight :: Number` and the `key`/`id` split all freeze on
  publish, and blobgraphs has not yet compiled against the real package.

## Explored But Not Pursued

- **ShapedSteer `DAG.JSON` reconciliation** — checked, no collision. It is an
  application-state serialiser (cell values, executors, computation states),
  not an interchange format. Its ~400 lines of hand-written encode/decode pairs
  and its reimplementations of `traverse` and `note` are noted for the
  anti-synergy survey, not fixed.
- **A DuckDB shim for blobgraphs** — not needed. Their JSON already conforms
  (verified against their stated v1 shape, both the combined document and the
  two-result-set path), and DuckDB FFI already exists in the ecosystem.

## Findings

- **`toSim` targeted the wrong node type** and 11 passing tests missed it.
  `Hylograph.ForceEngine.Types.SimNode` (`index :: Int`, no `fx`/`fy`) is not
  what `Sim.setNodes` consumes — that is
  `.Simulation.SimulationNode` (`id :: Int`, plus `fx`/`fy`). Building the
  worked example caught it in minutes, because the compiler checked the output
  against the API it exists to feed. Tests asserting properties *of* an
  adapter's output cannot catch an adapter aimed at the wrong type.
- **Those `ForceEngine.Types` node/link types are dead** — zero importers
  anywhere, duplicates of `hylograph-d3-kernel`'s. Three codebases have written
  `type SimNode = SimulationNode` locally to route around the naming, including
  both visual tests inside the defining package.
- **`Hylograph.Internal.*` is the de-facto public API** — ~470 imports from
  outside `hylograph-selection`, 175 of them for `ElementType`, which is needed
  for every `elem` call. `Hylograph.HATS` already re-exports other Internal
  types by exactly the pattern needed; `ElementType` was left out.
- **JGF spec check** turned up two divergences: per-item custom data is
  `metadata` there and `attributes` here (now aliased), and the multi-graph
  `{"graphs":[…]}` form now gets a plain error instead of a baffling one.
- **`Data.Codec.Argonaut.Common.foreignObject` is a trap** — encodes an
  `Object` as an array of key/value pairs. `CA.jobject` is correct.

## Parking Lot

- A **visualiser for the checker**, built with Hylograph. Its findings are
  themselves about a graph, so showing them *on* the graph dogfoods the stack
  the format feeds.
- **Minard cannot see dead types**, because its reference edges are
  `function_calls` and types are never called. Every type has zero incoming
  edges, so a dead one is indistinguishable from a load-bearing one. The fix is
  a `type_references` edge table derived from the already-stored
  `declarations.type_ast` — no new extraction pass. Then dead types become
  isolated nodes in the force layout.
- Two detectors worth more than deadness: **duplicate structure** across
  packages (would have fired at the kernel split, when the fix was one line),
  and **repeated local workarounds** — N codebases independently aliasing the
  same API. The latter is the agent-era signature: not one large error but the
  same small one made N times, each locally defensible, none visible in a
  single diff.
- Methodology note. Agents dropped the cost of *change* by roughly an order of
  magnitude and did not drop the cost of *forgetting* at all, so the bottleneck
  moved. Dead code also tends to squat on the good names, because after a
  rewrite the survivor had to be named around the incumbent — which is why it
  misleads disproportionately. And types make the transformation safe while
  saying nothing about disposal: the gap sits exactly where the type system
  stops.
