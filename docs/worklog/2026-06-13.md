# 2026-06-13 — Stability Atlas: the reader-legibility pass

Continuation of the Stability Atlas (Jurist showcase, Marginalia #219).
Yesterday left M5 with the honesty meter done; today was about making the
instrument legible to a non-physicist — driven by Andrew's framing that
he won't publish work he can't himself understand, and that fixing that
unlocks it for everyone.

## Accomplished

- **Axis schematic** ("How to read the atlas"): a static canvas diagram —
  Sun, asteroid on an elliptical orbit, Jupiter on its orbit — anchoring
  the atlas's two axes. Semi-major axis → horizontal; eccentricity →
  vertical, with a dashed e=0 reference circle. Eccentricity drawn
  exaggerated (≈0.66) for legibility. Jargon kept precise and explained,
  not euphemised (Andrew's call: the audience self-selected for a
  PS-on-Julia backend).
- **Small multiples** ("Eight orbits, two ways"): eight asteroids picked
  at random across the belt (one per band, so the sample always spans the
  resonances), each integrated *in the browser* by Atlas.Dynamics (the
  same code the honesty meter proved bit-identical to Julia), drawn as
  paired thumbnails — inertial row (all near-identical ellipses) above
  rotating row (rosettes, bands, escapes). The picks are marked as
  numbered red squares on the atlas. Click any to stream it from Julia.
- **Two-up orrery**: replaced the frame toggle with rotating + inertial
  side by side, always both visible — so the rosette-vs-ellipse contrast
  reads at a glance.
- **Selected-pick indicator**: the chosen small multiple gets an accent
  border + bold caption; the line above states both selection routes
  (another thumbnail, or any atlas point for a custom orbit).
- Committed in four chunks: 42906c8 (exactly-rounded dt — a*sqrt(a) so
  browser and Julia agree to the bit), bd14308 (honesty meter + axis
  schematic + small multiples), 1cfd9cc (two-up orrery + selected
  indicator). All verified by headless-Chrome screenshots.

## Decisions Made

- **Kirkwood-gaps overlay: DROPPED, on evidence.** The plan assumed the
  computed atlas's dark stripes would align with the real belt's Kirkwood
  gaps. Measured against 282,529 real JPL asteroids: the real gaps are
  sharp (3:1 90% deep, 5:2 70%, 2:1 92%; a pile-up at 3:2 Hilda), but the
  computed atlas at 150 *and* 300 periods shows 0% loss and ~0% chaos at
  all three inner-gap columns — its only instability is near Jupiter
  (a > 0.7), which doesn't coincide. Reason: our integration is ~1,800–
  3,600 yr; the gaps form by chaotic e-pumping over ~10^5–10^6 yr (1000×
  longer), and a circular-Jupiter model wouldn't fully reproduce the 3:1
  mechanism anyway. "The map reproduces the gaps" is false; Andrew chose
  to skip the overlay rather than ship a claim he couldn't stand behind.
  (Exactly the explain-so-Andrew-can-stand-behind-it principle paying
  out: the value was catching the false claim before publish.)
- **No 3-D orrery** (decided earlier): the CR3BP is planar; 3-D would be
  cosmetic and misleading.
- **Feature-complete as a showcase** (Andrew). No more atlas features.

## Explored But Not Pursued

- Fully-static (all-browser) version: technically possible since the
  browser holds the bit-identical Atlas.Dynamics, but it would gut the
  showcase — the point is PS-on-Julia doing real server-side compute over
  a typed wire.

# 2026-06-13 (cont.) — purescript-go: Phase 1 conformance COMPLETE

Continued the PureScript→Go backend (psgo). Started the day at 3 corpus
modules green (72 tests); ended with **all 10 green** — the full Phase 1
conformance target.

## Accomplished

- **Full corpus green:** `422/426 identical, 4 known divergences, 0 failures,
  0 module errors`. Added this session: Dictionaries (42), Numbers (106),
  STTests (15), Arrays (85), Effects (14), Strings (72), and Recursion (16)
  came green for free. The 4 diffs are the seeded ledger entries — INT64
  (`sumTo 1e6`, `fact 20`: Go 64-bit ints don't int32-wrap) and ASTRAL
  (`CU.length`/`CU.take` on emoji: Go codepoints vs JS UTF-16 units) — both
  intentional 64-bit/UTF-8 target behaviour, not bugs.
- **Five general codegen/runtime fixes** (each surfaced by a new module, all
  fix latent correctness bugs, not module-local): `GoVarDef` (interface-typed
  `let` so closure-valued bindings can be applied via assertion);
  `_jsNumToString` (faithful ECMAScript Number::toString — Go `'g'` diverges on
  exponent thresholds/padding); `_toInt32`/`_toUint32` (JS int32 bitwise wrap);
  a **bijective reserved-word mangler** (PS `map` vs foreign `map_` were
  colliding into a strict CAF cycle); and per-alternative block scoping in
  `genCase` (equational clauses binding the same names).
- The runtime (`runtime/prelude.go`, embedded into psgo via file-embed) grew
  from ~56 core shims to the full Phase-1 foreign catalogue, staying gofmt-clean
  and standalone-compilable.

## Decisions Made

- **TCO trampoline (ADR-0003) deferred.** Recursion passes with no trampoline:
  Go's growable goroutine stack absorbed `sumTo 1e6` (1M frames). TCO is a
  Phase-2 *performance* concern, not a Phase-1 *correctness* one.
- All Data.String ops operate on Go **runes** (codepoints), matching JS for
  ASCII/BMP and diverging on astral exactly as the ledger predicts. CodeUnits
  index results converted byte→rune to stay codepoint-consistent.
