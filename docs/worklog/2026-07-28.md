## Decisions Made

- **Ship the repo, defer the registry.** Paul's producer is C++; it
  consumes the format, the example files and the checker, none of which
  need a registry release. Publishing is a *stability promise*, so making
  it for a shape no emitter has exercised is backwards. A GitHub repo
  unblocks him today; 0.1.0 can mean something later.
- **Patch bump for the `Internal` move (0.5.2), minor for the deletion
  (0.6.0).** Shims preserve the exact public surface, so promotion is
  purely additive and needed no downstream coordination. Removing exports
  is breaking by the letter of semver even with zero importers, because
  neither the registry nor any consumer can verify that claim.
- **No `extraPackages` override** to force `hylograph-selection` 0.5.2 into
  the worked example. It would trade a visible two-line comment for an
  invisible obligation to remember to remove it — the exact debt pattern
  this whole thread has been digging out of.
- **Path-scoped commits throughout.** Every repo touched had unrelated work
  in flight; `hypo-punter` alone had thirteen modified files including its
  own `landing/spago.yaml`. Nothing got swept up.
- **Uppercase `JTMS` deliberately not renamed** in three places describing
  Make's semantics as "monotone JTMS rules". Baskerville *is* a
  justification-based truth maintenance system; those sentences are about
  the concept, not the package. A blind search-and-replace would have
  turned correct terminology into a false claim.
- **The components demo committed but not wired in.** It is absent from the
  Makefile `DEMOS` list and unlinked from the site. Source first, because
  that was the part at risk; publishing a new demo page is a deliberate act,
  not a side effect of committing.

## Findings

**The diagnosis was wrong, and the truth was better.** The `Internal`
modules' headers had been saying *"use the public API in
`Hylograph.Behavior`"* — and `Hylograph.Behavior` was never written. Nor
`Hylograph.Transition`, nor `Hylograph.Selection`. The code was correctly
marked internal, the docs correctly redirected the reader, and the
destination did not exist. Those ~470 imports were not a boundary being
ignored; they were the only door in the building.

Generalising: a *misplaced* boundary and an *unfinished* boundary look
identical from outside — both present as consumers reaching into
`Internal` — and want opposite responses. Reading the module header
distinguished them, and took thirty seconds.

**Publishing does not make a version reachable.** Package sets pin versions
and *override* dependency ranges. Set 77.13.1 pins
`hylograph-selection: 0.5.1`, and so does the newest published set,
80.0.0. So the range widening across seven repos was necessary but not
sufficient — it prevents a conflict when the set advances, it does not
advance anything. The visible consequence is that the worked example still
imports `Internal` despite the fix being live.

**Two libraries were declaring `license: MIT` with no licence text**, five
releases each. Files added before publishing rather than making it a sixth.

**Relative paths are silently relative to something, and nothing records
what.** Three variants of the same hazard in one afternoon: a renamed repo
that could not warn its dependents; a `path:` dependency on a directory in
no repository; and a Makefile rule doing `cd $demo && spago bundle`, where
relative `path:` entries resolve against the *working directory* — so the
two demos with sibling-checkout dependencies could not be built by `make`
from anywhere. All three are the unidirectional-reference problem
(§6b of `plans/minard-for-operations.md`) wearing different hats.

**A commit can lie about itself.** The first rename commit moved the
directories but omitted the edits inside the moved files — `git status`
showed `RM`, which is renamed-in-index *plus modified-in-worktree*, and I
read the pair as both staged. The message described changes the commit did
not contain. Fixed in a follow-up; worth remembering that `R` and `RM` are
materially different.

**`simulation-halogen` was a hidden cascade point.** Published, and
depending on `hylograph-simulation <0.6.0`, so anyone wanting both would
have been stuck. Widening its bound required its own release to mean
anything — the sort of thing that is invisible until you enumerate the
dependency graph.

## Explored But Not Pursued

- **Deleting the deprecation shims.** Correct eventually, wrong now: the
  ecosystem has not migrated. `Test.DeprecatedPaths` guards them in the
  meantime, asserting in the type checker that old and new paths denote the
  *same* declarations rather than lookalikes.
- **The FFI leakage.** `Internal.Behavior.FFI` (18 imports), `Internal.FFI`
  (6) and `Internal.Transition.FFI` (2) are still reached into by
  application code. Deliberately left: those are genuinely internal *and*
  genuinely foreign, and consumers reach for them because no public wrapper
  exists. Missing API, not misplaced API — it wants wrappers, not a move.
- **Chasing `the-prelude`'s exact version pins forward.** It pins
  `hylograph-simulation: "0.5.0"` in `extraPackages`. Superseded, so the
  pins stay where they are — recorded in its README so it does not become a
  mystery later.

## Parking Lot

- A **visualiser for `graph-json-check`**, built with Hylograph. Its
  findings are about a graph, so showing them *on* the graph dogfoods the
  stack the format feeds.
- **Minard cannot see dead types** — its reference edges are
  `function_calls`, and types are never called, so every type has zero
  incoming edges and a dead one is indistinguishable from a load-bearing
  one. Fix is a `type_references` edge table derived from the
  already-stored `declarations.type_ast`. See the postscript in
  `research/hylograph-public-api-leaks.md`.
- **No Hylograph library has ever had CI** — surveyed after noticing the
  Pages workflow removal emptied `hylograph-selection/.github/`. It is 0 of
  18 packages, 16 of which are published. Written up as
  `kb/plans/hylograph-libs-ci.md`, with the central argument being *not* to
  write eighteen copies of the same workflow file — a reusable
  `workflow_call` with thin per-repo callers, since eighteen copies would
  drift exactly the way three independent `type SimNode = SimulationNode`
  aliases did.
- The **duplicate-structure** and **repeated-local-workaround** detectors,
  still the two highest-value ideas to come out of this thread.
