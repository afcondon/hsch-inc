## Key Insight

Treelikeness is architectural health. A clean layered architecture (DAG) has treelikeness near 100%. Every layer violation creates a cycle that merges biconnected components. minard-frontend's 4.1% treelikeness IS the accumulated architectural debt — the viz is honest. Decomposition can both diagnose the problem (descriptive) and suggest solutions (prescriptive layer discovery), complementing the planned enforcement pipeline.

## Decisions Made

- **Frontend-only decomposition**: algorithms run in browser on already-loaded import data. No server changes needed. O(V+E) on <1000 modules is instant.
- **Copy Decomposition.purs** rather than add hylograph-graph dependency. Cleaner until 0.2.0 is published.
- **Per-package scope buttons**: the key UX insight — workspace-wide (846 modules) is too big, individual packages are tractable and structurally interesting.
- **Feature C (layer discovery) first**: it doesn't depend on enforcement pipeline shipping, and its output (draft architecture.yml) feeds into the enforcement plan.
