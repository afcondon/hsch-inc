  refinement type verifier for PureScript, written in PureScript, solving
  with Z3. Took the January feasibility study
  (`kb/research/liquid-purescript-feasibility.md`) from paper to a working
  end-to-end vertical slice in one session (a deliberate Fable 5 run).
- **Detailed plan** at `liquid-purescript/docs/PLAN.md`: architecture

  measures/data → HOF → type classes).
- **Working slice**: `abs`, `clamp` (dependent spec across argument binders:
  `{lo:Int} -> {hi:Int|hi>=lo} -> Int -> {v:Int|v>=lo && v<=hi}`), `sign`
  (guards + `otherwise`), `double` (let) all prove SAFE; `bad n = n - 1`
  against `Nat` refutes with counterexample `n = 0` and correct source span;
  unknown calls (`min`) report UNSUPPORTED, never a silent pass. Golden test
  in `test/run.sh`.

## Ground truth discovered (matters for later phases)

- Spago emits CoreFn only via a custom backend (`workspace.backend.cmd`;
  `"true"` as no-op works). `--purs-args "--codegen corefn"` is rejected.
- Externs are CBOR in purs 0.15.15; `docs.json` is the JSON source for type
  signatures when Phase 1 wants signature cross-checking.
- purs floats type-class methods into synthetic module-local decls
  (`Demo.greaterThan = Data.Ord.greaterThan ordInt`), so the verifier has a
  resolution pass mapping local names → SMT primitives via (method, dict)
  pairs.

## Decisions Made

- External tool consuming CoreFn (no compiler fork) — carried from the
  feasibility study.
- Verifier written in PureScript (house style); Z3 via SMT-LIB2 text to the
  `z3` binary (`spawnSync`) — transport swappable for z3 WASM later
  (playground integration).
- Specs in separate `.lps` files, LH-flavoured syntax, aliases +
  dependent function specs; non-linear arithmetic rejected at parse time so
  every obligation stays in QF_LIA (decidable).
- Sound-but-imprecise defaults: anything outside the fragment errors
  honestly rather than passing.

## Night: Phase 2 first cut (same day)

Inductive ADTs via measures (commit 8fbc17f). `.lps` grows `data` and
`measure` declarations; data types are opaque SMT sorts characterized by
measures — constructor binders contribute `is<Ctor>` discriminators +
measure equations as path facts, constructor applications bind fresh
values with the same facts, measure result refinements instantiate at
every application (quantifier-free throughout).

Proved inductively: `count l == len l`, `len (append a b) == len a + len b`,
`len (singleton x) == 1`. Refuted: `badCount` (drops the +1). Parser
gained juxtaposition application (`len xs`), which required reserved
words — the application parser was swallowing a following `type` keyword
as an argument.

Three phases of the roadmap now have running code, all in one day.
Phase 2 remaining: Arrays (built-in length measure), trivial polymorphism
lifting, selectors, flat records.
