# 2026-07-26 — The unguarded-trigger sweep: two runaways, one shape

Started as "land the Observer fix from this morning's diagnosis" and became
an ecosystem-wide hunt for the same defect shape. Two instances found and
fixed, ten codebases cleared, one abstraction deliberately *not* built.

## Accomplished

- **minard-for-nix — Observer ingest-runaway fixed** (`67da24e`, pushed to
  `main`). The brief from this morning's session
  (`docs/observer-race-fix-brief.md`) landed in full:
  - **Single-flight per ingest kind with trailing coalesce**, with *every*
    trigger routed through it — the three timers, the `/nix/store` watcher,
    and the manual HTTP refresh. The manual path now shares the timers' keys
    *and* their hash-tracking, so it can neither race them nor leave
    `lastHash` stale for the next tick to beat spuriously.
  - **`MAX_INFLIGHT` spawn cap** as a backstop, so no future caller can
    fork-bomb regardless of guards.
  - **Child tracking + SIGTERM on drain**, instead of orphaning in-flight
    ingests to launchd.
  - **Split `drain()` out of `shutdown()`** — it conflated closing handles
    with `process.exit(0)`, so nothing could stop the observer without
    killing the process. That was what made the wiring untestable.
  - **Cadences read at start time, not module load** (`MINARD_FLEET_MS` &c.),
    so tests can compress them.
  - **Bounded every Bosun surface read** in `Chair.purs` (see Decisions).
  - `test/observer-guard.test.mjs` (`npm run test:observer`, 5 tests):
    the guard's invariants directly, plus the real trigger wiring against
    real child processes with fake slow ingest scripts. **Verified to fail
    with the guard removed** (`estate: expected <= 1 concurrent ingest, saw
    3`) — it catches the pileup, not just the arithmetic.
  - Supervised server restarted via `POST :3993/control/restart`; peak
    concurrent `ingest-estate` **1** over 65 s of sampling, zero orphans.

- **Ecosystem sweep for the same shape** — four parallel searches across
  ten codebases in four runtimes (Rust, Node/PureScript, BEAM, Go/Python).
  **Clean:** es9-daemon, link-spike, msm, msm-web, bosun, calypso,
  fh2-config, CodeExplorer, deepstar, worklog-server, polyglot-deploy.
  Bosun deserves specific credit — every timer is deliberately guarded
  (single-flight `ensureBackend`, launch-memory + backoff explicitly
  commented as defending against "the relaunch storm", `--max-time` on
  every probe). Only nit in that set: `Chair/Main.purs:366,375,496` polls
  `AX.get` with no timeout — a wedge, not a pileup.

- **purerl-tidal — vmod catch-up storm fixed** (`14720a9` on branch
  `odonus-cv-saich`, cherry-picked to `main` as `b813200`; both pushed). The
  branch was 18 commits ahead of main and never touched these three voices, so
  the pick was semantically equivalent, not merely conflict-free — verified by
  recompiling and re-running all 26 tests on main before pushing. The one other
  instance of the shape, in a different disguise.
  `balistes_voice`, `odonus_voice` and `repetitor_voice` resumed each cast
  at `last_step + 1` with no clamp to the clock, so the emitted window was
  as wide as the clock jumped. The `> 8` case recorded a `voice_step_burst`
  row and then **fell through and emitted the whole range** — detected and
  logged, never bounded.
  - Extracted the rule into **`src/tidal_step_window.erl`** rather than
    copying reef's clamp into three modules, so there is one documented
    statement of the invariant the voices cannot drift from.
  - `test/tidal_step_window_tests.erl` (`make test-erl`, 26 tests) — new
    `test-erl` target, since the existing suite is PureScript-driven and
    cannot reach hand-written Erlang modules.

## Decisions Made

- **The estate ingest's fetches are bounded inside `tryText`, not at each
  call site.** One edit covers all nine round-trips. Uses
  `parOneOf [ …, delay httpTimeout $> "" ]` rather than an explicit
  `AbortController`: killing the losing fiber makes the `fetch` library's
  existing canceler fire a *real* abort, so the socket is released rather
  than merely ignored. 3000 ms against measured ~1 ms localhost
  round-trips.
- **`runFlakeImpl` is deliberately NOT single-flighted.** Unlike the
  ingests these are distinct mutations parameterised by path, so coalescing
  two would silently drop a project's write. The `MAX_INFLIGHT` cap still
  bounds them.
- **The vmod clamp threshold is computed, not reef's fixed `?SNAP_AHEAD`
  of 8.** The vmod voices' legitimate lookahead is
  `lookAheadMs / cycleDurationMs * StepsPerCycle`, which grows with tempo
  *and* step resolution. Measured: balistes (32 steps/cycle) legitimately
  runs **7** steps ahead at 240 bpm and **13** at 480 — so a fixed 8 would
  snap during ordinary playback and shred it, and was already one step from
  breaking at moderate tempi. The clamp derives its threshold from the
  window the clock just supplied, ~4× headroom, floored at 8 so it is never
  tighter than reef's.
- **Missed steps are discarded, never replayed.** For a musical event, late
  is not merely worse than on-time, it is worse than never. Snaps record a
  `voice_step_snap` row so the discontinuity stays visible.
- **Did not build the abstraction** (see Parking Lot).

## Explored But Not Pursued

- **Dropping the store + toolchain sources from minard's estate path.**
  Measured, then deliberately left for AFC. Empirically: patched
  `estateModel` to use `emptySource` for both, rebuilt, ran against an
  isolated `MINARD_ROOT` — `topology.json` and `fleet.json` came out
  **byte-identical** (modulo `generatedAt`) and the ingest went
  **5.65 s → 0.34 s**. It is provably dead work on that path:
  `Projection.projectTopology` drops `DStoreFamily`/`DToolchain` outright
  and `projectFleet` only walks `Hosts` edges, and `writeViews` is
  `estateModel`'s only consumer. Not taken because it touches the one-model
  intent of ADR 0002/0003 — a decision, not a patch. Experiment reverted.
- **Blessing the 2.7 MB `store.json` with a no-op FFI coerce instead of
  decoding it** (AFC's suggestion). More defensible than it first sounds —
  it is our own ingest's output from one process ago, not a foreign wire —
  but it is the wrong boundary to cheat on (parse-don't-validate is that
  module's stated design; shape drift would surface as a wrong map rather
  than an error), and it optimises a decode that should not happen at all.
- **`Tidal/OSC.erl`'s spawn-per-event** and the **FH-2 shell-out race** in
  `Handler.erl:1140,1247` — both real, both left. See Parking Lot.

## Parking Lot

- **minard's fleet cadence.** The guard converts an unbounded runaway into
  one ingest running back-to-back **forever at ~107 % of a core**, because
  the 5.65 s ingest outruns its own 5 s timer. Three options in
  `docs/observer-race-fix-brief.md` §9: skip the dead sources (best, needs
  an ADR call), raise `MINARD_FLEET_MS` (now a one-line env change, no
  rebuild — the quick lever), or bless the JSON (weakest).
- **The brief's "normally sub-second" was wrong.** It is ~5.6 s. So the
  estate ingest has been outrunning its timer under *normal* conditions all
  along; the Mycroft/kibitzer batch of 2026-07-25 made the runaway visible,
  it did not create it.
- **`Tidal/OSC.erl` spawn-per-event** — a fresh process + UDP socket per
  event, no in-flight tracking. Much harder to provoke now the clamp is in,
  but still unbounded if anything else bursts.
- **`Handler.erl:1140,1247`** — a ~7 s `os:cmd` FH-2 read-modify-write
  spawned per WS message with no guard. The load path's own comment
  (`:1985-1989`) concedes parallel invocations clobber each other; safe for
  hand-typing, *not* safe for a Calypso cell re-fire or any client that
  re-sends on save.
- **`Chair/Main.purs` poll-loop `AX.get` has no timeout** — wedge risk.
- **`repetitor_voice` was meant to have been removed as obsolete** but is
  still fully wired: `tidal_clock.erl:182` broadcasts to
  `repetitor_voice_sup` every tick and `tidal_session_walker:494` can start
  voices. Patched today because it is live; the removal is still open.
- **The abstraction** — see below.

## Next Session Setup

- Both commits are **pushed**: minard-for-nix `main` at `67da24e`;
  purerl-tidal `main` at `b813200` and `odonus-cv-saich` at `14720a9`. That
  feature branch should probably have merged before now — the clamp landing on
  main first means the eventual merge is a no-op for these files.
- The open minard decision is the stratification question, not the fix:
  a fast tick must not rebuild a slow-cadence stratum. The change-rate
  strata already exist one layer down (store on `fs.watch` + 30 s,
  toolchain 10 min, estate 5 s) and `estateModel` collapsed them.
- **Deferred by decision: the "cursor against a moving authority"
  abstraction.** Both bugs were the same wrong answer — *replay the whole
  backlog* — to a question nobody was asked: the world moved while you were
  working, what happens to the backlog? Three legal answers: coalesce to
  one, snap to now and discard, replay all (only when provably bounded).
  The FP shape that fits is the **Store comonad** (`Store s a = (s -> a, s)`
  — position plus a function from positions to values; `seek` *is* the
  snap), and it explains why the two cases wanted *opposite* policies:
  minard's index is degenerate (a singleton "latest", so coalesce and snap
  collapse), the voices' is dense (the backlog is a range, so
  replay-or-discard becomes a real question with a wrong answer).
  **Not built:** n=2 with one degenerate is not enough to know which
  flavours are real, and Store names the shape but carries none of the
  safety — the bug-preventing part is a mandatory three-constructor policy,
  not a comonad. Revisit at a third instance; if its policy is neither
  coalesce nor snap-and-discard, the sum type is wrong.
- **Wider lesson (AFC's):** this class is not type-catchable — it wanted
  TLA+ or similar. And if a design wants full reconciliation over all
  sources, it has to allow time for it and say so, rather than leaving a
  completeness claim and a latency claim on separate pages.
