### Quartermaster Menagerie (behavioural, dual-runtime)
- `scripts/qm-menagerie.sh` + `docs/MENAGERIE.md`. The analog of Bosun's
  Menagerie, fitted to provisioning: Bosun's launched live processes and watched
  supervision; Quartermaster launches nothing, so its muscle is the **probe edge**.
  Specimens are controlled host conditions; each scenario *flips* one (a runtime
  on/off PATH, a cwd present/absent, a binary executable or not), runs `verify`
  under both node and gnomon, and asserts node ≡ gnomon **and** the verdict moves
  correctly.
- This exercises the probe foreign's **absence path** (`command -v <missing>` →
  node `execSync` throws, Go `exec` errors, both must report `RuntimeMissing`)
  that the static byte-diff never hits (its fixtures probe whatever the dev box
  has). Hermetic `/tmp` stage, offline by default, opt-in remote ssh scenario.
  Five scenarios, all pass. Commit QM `c29de33`.

### Live `quartermaster build` wired up
`build` is now live by default (`--dry-run` = plan, `--no-push` = build without the
outward push), mirroring `bosun apply`. Each build-from-source service runs
`docker build && docker push` on its build host — ssh-wrapped for a remote target,
in the target's workdir (the context is relative to it), with the target's
`envPrefix`. New streaming exec edge (`Quartermaster.CLI.Build` + JS/Go foreign
twins, inherited stdio so docker progress streams). `buildInvocation` is the single
pure string the CLI both displays and runs.

Proven live in **both matched lanes** against the real mini: node and the gnomon
native binary each built + pushed the polyglot `edge` image to `localhost:5001`,
**same digest** (`cbd39704…`). Commits QM `8a5771c`, bosun `9946f92`.

Two real bugs surfaced and fixed in the doing:
1. The `-f` Dockerfile path: compose resolves `dockerfile` relative to `context`,
   but raw `docker build -f` resolves it relative to CWD — so `buildPlan` must join
   them (`<context>/<dockerfile>`) or the Dockerfile is missed.
2. The macOS keychain is locked over a non-interactive ssh session, so the
   `desktop` docker credential helper fails even for an anonymous docker.io
   base-image pull. Fixed by `DOCKER_CONFIG=/Users/andrew/.docker-nocreds` (a
   docker config with no `credsStore`/`currentContext` + a `cli-plugins` symlink so
   `docker compose` still resolves), carried in the macmini target's `envPrefix`.
   The first attempts taught it the hard way: an empty config breaks compose-plugin
   discovery; keeping `currentContext` breaks the context lookup over the override.
   That nocreds dir is manual host prep — a future `quartermaster` provisioning
   check.

## Decisions Made
- **Matched-lane testing** (user): test all-node and all-gnomon as pairs; do NOT
  cross QM-Go × Bosun-Node etc. The two tools move together in their runtime.
- **The mini polyglot deploy is disposable** (user): free to apply/down on every
  test, even though it's nominally public.
- Provisioning-probe behavioural conformance is a *flip* harness, not a snapshot —
  the absence path is the part static fixtures structurally cannot cover.
