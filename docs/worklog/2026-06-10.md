- **Increment 5 — the differentiation round-trip, typeset** (commit `a5b1c8f`).
  Hand a `NumExpr` across the seam; Julia binds its variables to Symbolics
  scalars, differentiates symbolically, and hands the derivative **back as LaTeX**
  (`Latexify`). `Data.Differentiate` (+ FFI) exposes `exprLatex` / `gradientLatex`
  over (declare-vars, wrt-vars) — a Jacobian row declares state+params but
  differentiates by state. `Main` differentiates a showpiece (`10x² − xy + sin y +
  log x`, whose ∂/∂x is `20x − y + 1/x`) and the **Lorenz analytic Jacobian**
  (`[−σ, σ, 0; ρ−z, −1, −x; y, x, −β]`), writing `derivatives.json`. `diff-viz/`
  is a static **KaTeX** page (light/Swiss) rendering it at publication quality —
  real stacked fractions, σ/ρ/β (Greek names mapped from Latexify's `\mathtt{…}`).
  "Descriptions across, **descriptions back**": what returns is math you can read.
  Screenshot verified via headless Chrome. julia-env gained `Latexify`.

- **Increment 6 — rigorous root finding, proofs not guesses** (commit `df03ead`).
  Hand a single-variable `NumExpr` to Julia's **`IntervalRootFinding`**, which
  doesn't just find roots — it **proves** them: each root bracketed in a
  guaranteed enclosure and certified `:unique`, the search exhaustive (none
  missed), and an empty result is itself a proof. `Data.Roots` (+ FFI) builds a
  single-var RGF from the JExpr; IntervalArithmetic overloads the ops, so the same
  RGF that runs on Float64 runs rigorously on a *box* (powers as products so it
  stays valid over negative x). `Main` proves the roots of four functions:
  `x³−2x−5` (1), `sin x − x/3` (3), **`x²+1` (proven NONE)**, `x⁴−10x²+9` (4),
  writing `roots.js`. `roots-viz/` is a static page (KaTeX + an SVG plot) drawing
  each curve with its proven roots marked and the verdict spelled out — same
  `window.ROOTS`/`file://` trick, no server. The "no real roots" case is the
  discriminator: a certificate scipy/JS can't give. julia-env gained
  `IntervalArithmetic` + `IntervalRootFinding` (resolve cleanly beside MTK).

- **Increment 7 — provably-optimal MILP, a new verb (optimize)** (commit `eb6c0c2`).
  Hand a typed 0/1 knapsack to Julia's **`JuMP`/`HiGHS`** mixed-integer solver; it
  returns the optimal selection **and the proof** (status OPTIMAL, relative gap 0).
  `Data.Optimize` pairs the `knapsack` FFI with a pure-PureScript `greedyValue`
  baseline: greedy grabs the best value/weight item (Telescope, 12) and stalls;
  the solver proves the true optimum is Camera+Tripod (**18**). `opt-viz/` shows
  the two side by side — the un-dismissable "you can't just eyeball it" point.
  FFI macro gotcha: inside the generated module the sense/binary tags must be
  `JuMP.MAX_SENSE` + `binary = true` (not bare `Max`/`Bin`) — validated in a
  standalone-module probe first. julia-env gained `JuMP` + `HiGHS`.

- **Tier-3 keystone — AlgebraicJulia: Petri nets → functorial dynamics** (commit
  `0f57805`). A new self-contained example **`examples/petri-catlab`** (its own
  `julia-env` with Catlab + AlgebraicPetri + OrdinaryDiffEq, isolated from the
  MTK/JuMP env). A typed Petri net described once in PureScript (`Data.Petri`:
  species + transitions with input/output multiplicity + rate); **AlgebraicPetri**
  derives the mass-action ODEs *functorially* (`vectorfield`) and `OrdinaryDiffEq`
  solves them — PureScript never writes a differential equation. `odeLaws` returns
  the derived ODEs as LaTeX (built from the net stoichiometry Julia-side). SIR +

## Decisions Made

- **Shared `core` package (path dep), not glob-shared source.** Andrew chose the
  layout where `core` is a real spago package both denotation workspaces depend
  on — "one description, N denotations" expressed in the build graph. The
  alternative (each workspace globbing the same `../src` files) was lighter but
  left the sharing implicit.
- **`*.Julia` submodule naming** for the denotation (`Data.NumExpr.Julia`,
  `Data.SystemSpec.Julia`) — purejl maps the dotted name to
  `Data_NumExpr_Julia_foreign.jl`, so the ffi shim rename is mechanical.
- **Two workspaces, not one**, because `backend: cmd "true"` (purejl) and the JS
  backend are workspace-level settings — they can't co-exist in one `spago.yaml`.
- **Committed straight to `main`**, matching this repo's established increment
  rhythm (CI gates on main; prior session landed four increments there).
